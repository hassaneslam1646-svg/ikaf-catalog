# تحديث الكتالوج

مجلد `build/` فيه السكريبت اللي بيبني الموقع كله من ملف الكتالوج PDF.

## الخطوات

```bash
python3 build/build.py "الكتالوج الجديد.pdf" "شجرة اكواد الجلابية.xlsx"
git add -A
git commit -m "تحديث الكتالوج"
git push
```

بعد الـpush بدقيقة أو اتنين GitHub Pages بيبني لوحده، واللينك بيفضل زي ما هو:
**https://hassaneslam1646-svg.github.io/ikaf-catalog/**

## السكريبت بيعمل إيه

1. يحوّل كل صفحة في الـPDF لصورة ويقرا الكود من الشريط البرتقالي (OCR).
2. يفك الكود حسب شجرة الأكواد: خانة 9-10 = الريشيو، خانة 5-6 = الموديل
   (ومنه العرض لو مذكور في اسم الموديل).
3. يكتب الريشيو بالأبيض جنب شريط الكود على كل صفحة → `out/labeled.pdf`
4. يطلّع صور الموقع: `thumb/` (مقصوصة على المنتج) و `full/` (الصفحة كاملة).
5. يبني `index.html` من `build/template.html`.
6. يطلّع `out/review.xlsx` — جدول لمراجعة كل صنف وريشيوه.

`out/` مش بيتحفظ في المستودع (موجود في `.gitignore`).

## لازم تراجع

السكريبت بيقف ويطبع تحذير في حالتين، والصنف بيتساب بره الموقع لحد ما تتراجع:

- **كود مش مقروء:** الشريط البرتقالي في الصفحة مش واضح.
- **كود مش موجود في الشجرة:** ريشيو أو موديل جديد لسه مضافش لملف شجرة الأكواد.

الحل في الحالة التانية إنك تضيف السطر الناقص في شيت `ARABIC` وتشغّل السكريبت تاني.

## حالات خاصة متعامَل معاها

| الحالة | اللي بيتكتب |
|---|---|
| `مقاس B` | `B` |
| `مقاس B` + موديل "نصف كم عادى عرض 24" | `B24` |
| `مقاس A` + موديل "عرض مخصر (slim fit-22:24)" | `A22/24` |
| موديل فيه "عرض عادي" | الريشيو لوحده من غير رقم |
| ريشيو `99` (`speichal`) | `SPECIAL` |
| `Free Size` | `FREE` |

## المتطلبات

```bash
apt install poppler-utils tesseract-ocr
pip install pillow numpy openpyxl pypdf reportlab
```

وخط `Poppins-Bold.ttf` (نفس خط الكتالوج). السكريبت بيدوّر عليه في خطوط
النظام، ولو مش لاقيه حطّه في `build/Poppins-Bold.ttf`.

## لو قالب الصفحة نفسه محتاج تعديل

`build/template.html` هو الصفحة بالظبط، بس مكان بيانات الأصناف فيها
مكتوب `__DATA__`. عدّل فيه زي ما تحب وشغّل السكريبت تاني.

## صور الأصناف وكميات المخزون (merge_photos.py)

بعد `build.py`، أو لوحده لما المخزون أو الصور يتغيروا:

```bash
python3 build/merge_photos.py "<فولدر الصور>" "<تقرير المخزون>.xlsx" "<شجرة الأكواد>.xlsx"
```

- فولدر الصور: ناتج `prepare_site_images.ps1` على الجهاز — صور باسم الكود 14 رقم،
  والصور الزيادة لنفس الكود `<الكود>_2.jpg` ...
- الكمية لكل صنف (حتى أصناف الـPDF) = عمود "المستودعات الرئيسية" من شيت "المخزون".
- صور أصناف الـPDF بتتضاف كصور إضافية للصنف (تتقلب في نافذة الصنف).
- الأكواد الجديدة بتتضاف لو رصيدها 20 أو أكتر، والريشيو من الكود بالشجرة.
- الصور بتتكتب في `photos/full` و `photos/thumb`.
- لو اتشغّل `build.py` تاني لازم `merge_photos.py` يتشغّل بعده عشان الصور ترجع.
- كل صنف بياخد اسم الخامة من الشجرة (خانة 2-3 من الكود، شيت ARABIC عمود C/D)،
  وبيظهر فلتر خامات تحت فلتر الريشيو في الصفحة، والفلترين بيشتغلوا مع بعض.
- الكميات بتظهر من غير كسور (بتتقرب للرقم الأقل).
- `build/overrides.json`: كميات المستخدم عدّلها بإيده، وبتغلب على تقرير المخزون في كل تحديث.
- `build/excluded.json`: أكواد متشالة من الكتالوج بطلب المستخدم (حتى لو ليها مخزون).
- الصور المكررة بتتشال تلقائي: لو الصورة هي نفسها، أو نفس المجموعة اللونية (نفس مربعات COLORS) - بتفضل صورة واحدة لكل مجموعة لونية، وصفحة الـPDF ليها الأولوية.
- `build/drop_photos.json`: صور بعينها المستخدم أكد إنها مكررة، بتتشال حتى لو الفحص التلقائي ما لقطهاش.
- تاريخ التحديث بيتكتب جنب "تحديث المخزون" لوحده كل ما الصفحة تتبني (توقيت الرياض).
- نافذة الصنف: الكمية الإجمالية وتحتها تفصيلة المخازن (الرياض/جدة/مكة)، وزرار واتساب بيبعت الصورة + الكود والريشيو والموديل والخامة (من غير الكمية).
